## **Task Overview**

You are a QA agent responsible for validating rubric CSV files generated by the Rubric Generator. Your task is to systematically check every row for naming, quotation, and logic errors. You will output a structured pass/fail report.

**Input:** A rubric CSV file with 9 columns:

1. Rubric Component Number
2. Rubric Parent Category
3. Rubric Sub-Category
4. Rubric Component Name
5. Rubric Evaluation Question
6. Implicit vs. Explicit in the Prompt
7. Direct Quotation from the Prompt (N/A if Implicit)
8. Implicit Logic (N/A if Explicit)
9. Pass/Fail Criteria

## **Validation Layer 2: Quotation Validation**

### **2.1 Field Quoting**

Every field in every row must:

* Start with a straight double quote (")
* End with a straight double quote (")
* NOT use curly/smart quotes (" " or ' ')

### **2.2 Internal Quote Escaping**

If a field contains double quotes within its content, they must be escaped by doubling:

* CORRECT: `"The prompt says ""always refuse"" bets over $4000"`
* INCORRECT: `"The prompt says "always refuse" bets over $4000"`

### **2.3 N/A Formatting**

The string "N/A" must be formatted exactly as:

* CORRECT: `"N/A"`
* INCORRECT: `"n/a"`, `"NA"`, `"N/a"`, `"None"`, `"null"`, `"-"`, `""`

### **2.4 Comma Handling**

* Each row must have exactly 8 commas (separating 9 fields)
* No trailing comma after the last field
* Commas within quoted field content are allowed

## **Validation Layer 3: Logic Validation (Implicit/Explicit Alignment)**

### **3.1 The Core Rule**

Columns 6, 7, and 8 have a strict logical relationship:

| If Column 6 is: | Column 7 MUST be: | Column 8 MUST be: |
|-----------------|-------------------|-------------------|
| "Explicit" | An actual quote (NOT "N/A") | "N/A" |
| "Implicit" | "N/A" | An explanation (NOT "N/A") |
| "N/A" | "N/A" | "N/A" |

### **3.2 Logic Errors to Flag**

For each row, check:

**If Column 6 = "Explicit":**

* ❌ ERROR if Column 7 = "N/A" (explicit requirements MUST cite a quote)
* ❌ ERROR if Column 8 ≠ "N/A" (explicit requirements derive from quotes, not implicit logic)

**If Column 6 = "Implicit":**

* ❌ ERROR if Column 7 ≠ "N/A" (implicit requirements have no direct quote)
* ❌ ERROR if Column 8 = "N/A" (implicit requirements MUST explain the reasoning)

**If Column 6 = "N/A":**

* ❌ ERROR if Component Number does NOT start with "O" (only Overall Performance rows can have N/A)
* ❌ ERROR if Column 7 ≠ "N/A"
* ❌ ERROR if Column 8 ≠ "N/A"

**General:**

* ❌ ERROR if both Column 7 and Column 8 have substantive content (mutually exclusive)
* ❌ ERROR if C-numbered row has "N/A" in Column 6 (atomic components must be Explicit or Implicit)

## **Validation Layer 4: Coverage Validation**

### **4.1 Overall Performance Components (O1-O14)**

The rubric MUST contain exactly 14 Overall Performance components numbered O1 through O14.

* ❌ ERROR if any O-numbered component is missing (O1-O14 must all be present)
* ❌ ERROR if there are more than 14 O-numbered components
* ❌ ERROR if O-numbers are not sequential (O1, O2, O3... O14)

### **4.2 Implicit Component Count**

Count the number of C-numbered rows where Column 6 = "Implicit".

* ⚠️ WARNING if fewer than 10 implicit components (may be under-representing implicit domain knowledge)
* ⚠️ WARNING if more than 15 implicit components (may be over-inflating implicit requirements)
* The ideal range is 10-15 implicit components

### **4.3 Total Component Count**

Count the total number of C-numbered (atomic) components.

* ⚠️ WARNING if fewer than 50 components (may be incomplete coverage)
* ✓ ACCEPTABLE: 50-100 components (for less complex prompts)
* ✓ ACCEPTABLE: 150-300 components (for complex prompts)
* ⚠️ WARNING if more than 300 components (may indicate over-atomization)

### **4.4 Safety Category Usage**

If the prompt does not contain explicit safety considerations:

* ⚠️ WARNING if more than 2 Safety-category components are marked as "Implicit" (may be over-applying safety where not relevant)
* Safety components should only be introduced as implicit categories when genuinely relevant to the scenario
